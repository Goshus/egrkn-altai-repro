# s00_fetch_boundaries.py — инструкция авторам для локального запуска

Скрипт `src/s00_fetch_boundaries.py` получает границы трёх пилотных районов из OpenStreetMap
(сервис Nominatim, лицензия ODbL 1.0) и сверяет их с замороженными в репозитории.
В среде агента запуска не проверялся — доступа к API Nominatim нет; инструкция предназначена
для локального запуска авторами на машине с доступом в интернет.

## Идентификаторы OSM (из properties.osm_id замороженных файлов)

|---|---|---|---|---|---|

| data/boundaries/boundary_2.json | Красногорский | R (relation) | 1150926 | 3953 | 3f16453b645c13f17aa570b1da9bd67fbeb10edc64e8208e76b59f567429a323 |
| data/boundaries/boundary_3.json | Солтонский | R (relation) | 1150924 | 2213 | 97c15ebfaf43e593724350a973fce80acfe1ef4fb6eb234234999ed0b74b90b2 |

## Режим --verify (без сети): сверка замороженных границ

Проверяет, что файлы `boundary_*.json` в `--boundaries-dir` побайтово совпадают с эталоном
в `--frozen-dir` (в репозитории это та же папка data/boundaries/). Сети не требует.

```bash
python src/s00_fetch_boundaries.py --mode verify \
    --boundaries-dir data/boundaries \
    --frozen-dir data/boundaries
```

**Ожидаемый результат:** для всех трёх файлов вывод
`boundary_N: <sha256> == <sha256> → совпал`, код возврата 0.
При расхождении — `РАСХОЖДЕНИЕ` и код возврата 1 (файл изменён вручную; восстановить из репозитория).

## Режим --refetch (требует сеть, доступ к nominatim.openstreetmap.org)

Запрашивает актуальную геометрию трёх relation через Nominatim (`polygon_geojson=1`),
без перезаписи замороженных файлов, и сравнивает по числу вершин с замороженными.
Кэш ответов сохраняется в `--cache-dir` (по умолчанию `cache_nominatim/`).

```bash
python src/s00_fetch_boundaries.py --mode refetch \
    --boundaries-dir data/boundaries \
    --cache-dir cache_nominatim
```

**Ожидаемый результат** (при неизменных границах в OSM):
```
  Змеиногорский (osm_id=1083293): заморожено вершин 3484; запрос к Nominatim…
    получено вершин 3484; совпадение по числу вершин: True
  Красногорский (osm_id=1150926): заморожено вершин 3953; запрос к Nominatim…
    получено вершин 3953; совпадение по числу вершин: True
  Солтонский (osm_id=1150924): заморожено вершин 2213; запрос к Nominatim…
    получено вершин 2213; совпадение по числу вершин: True
```

Возможные отклонения и их трактовка:
- Число вершин отличается — в OSM редактировали границу района после выгрузки (замороженной
  даты). Не ошибка воспроизводимости, а обновление источника; зафиксировать новую дату выгрузки
  и при необходимости обновить замороженный файл через `--mode fetch` (только для первичной
  выгрузки/обновления), пересчитать geo_diagnostics и geo_boundary_distances.
- `запрос не выполнен: ...` — нет сети / Nominatim недоступен / превышен лимит. Пауза 1 с между
  запросами и обязательный `User-Agent` уже учтены; при 429 (Too Many Requests) увеличить паузу.

## Режим --fetch (только первичная выгрузка/обновление)

Запрашивает и сохраняет геометрию (через тот же код, что и --refetch). Использовать
только для первичной выгрузки или планового обновления замороженных границ; не применять
в рутинной проверке воспроизводимости.
